# 安装脚本指引

## 作用域

- 本文件适用于 `modules/` 下的安装与配置脚本。
- 继续遵循仓库根目录的 `AGENTS.md`；以下规则只约束安装脚本。

## 脚本设计

- 每个模块提供一个可直接执行的安装入口，并用 `--help` 说明参数、默认行为和会修改的位置。
- 需要支持 `curl | sh` 或 `curl | bash` 的入口必须自包含；不能假定仓库已克隆。读取仓库配置时，优先使用本地目录，并提供可覆盖的远程来源作为回退。
- Bash 脚本使用 `#!/usr/bin/env bash` 和 `set -euo pipefail`；仅使用 POSIX 语法的脚本使用 `#!/bin/sh` 和 `set -eu`。不要在 `/bin/sh` 脚本中加入 Bash 专用语法。
- 把可调整的下载地址、配置来源和目标路径集中定义在脚本开头，并允许通过参数或环境变量覆盖需要测试或镜像替换的值。
- 解析参数时拒绝未知参数和缺失值；执行系统修改前先检查运行用户、操作系统、包管理器和必需命令，并输出可执行的错误信息。
- 不要让整个脚本以 root 身份运行。只对安装系统软件包等必要命令使用 `sudo` 或等价提权，用户目录中的文件始终以当前用户身份写入。
- 重复执行脚本必须保持可预期：托管配置块应先移除旧块再写入；整体替换现有配置前应备份；复制目录时不得删除与本模块无关的用户文件。
- 下载脚本、压缩包或软件包时使用失败即退出的选项；可获得校验值时必须校验。临时文件使用 `mktemp` 创建，并通过 `trap` 清理。
- 将“安装依赖”“获取配置”“写入配置”“启动或激活”拆成独立函数。提供跳过安装、仅更新配置或不启动服务的选项时，各模式不得执行未选择的阶段。
- 不要静默忽略关键安装或配置失败。只有非必需工具、进程本来未运行等允许降级的情况才能使用 `|| true`，并输出跳过结果或后续操作提示。

## 验证

- 修改脚本后，按解释器运行静态语法检查：Bash 使用 `bash -n modules/<name>/<script>.sh`，POSIX shell 使用 `sh -n modules/<name>/<script>.sh`。
- 环境中存在 ShellCheck 时，对改动脚本运行 `shellcheck modules/<name>/<script>.sh`。
- 参数分支或文件复制逻辑发生变化时，使用临时目录和伪造命令做最小测试。除非用户明确要求，不要在验证阶段真实安装软件包、修改系统配置或启动桌面服务。
- 新增或修改对外参数、默认行为或一键安装入口时，同步更新 `README.md` 中对应示例。

## 维护

- 安装入口、支持的运行方式、配置目录或验证命令变化时，同步检查本文件，删除已经失效的规则。
